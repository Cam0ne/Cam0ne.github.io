x86 标志寄存器解析

发表于2026-08-10|更新于2026-08-10|逆向

基本概述

在逆向分析里，很多跳转、循环和条件判断并不是直接判断某个变量，而是在判断 CPU 标志寄存器里的标志位。

例如 cmp eax, 1 之后的 je，并不是 je 自己完成比较，而是 cmp 先影响标志位，je 再根据零标志位 ZF 决定是否跳转。理解标志寄存器，才能真正看懂 cmp、test、add、sub 和各种条件跳转之间的关系。

标志寄存器是什么

标志寄存器用于保存 CPU 运算后的状态。每个标志位只关心一种特定状态，例如结果是否为 0、是否发生进位、是否溢出、结果最高位是否为 1 等。

常见的几个标志位如下：

标志位 名称 主要用途
CF Carry Flag 无符号运算是否进位或借位
PF Parity Flag 结果最低字节中 1 的个数是否为偶数
AF Auxiliary Carry Flag 低 4 位是否向高 4 位进位或借位
ZF Zero Flag 运算结果是否为 0
SF Sign Flag 运算结果最高位是否为 1
OF Overflow Flag 有符号运算是否溢出
DF Direction Flag 字符串指令的地址移动方向

逆向时最常见的是 CF、ZF、SF、OF，它们经常参与条件跳转判断。DF 更多出现在字符串操作指令里，例如 movs、lods、stos。

CF：无符号进位与借位

CF 是 Carry Flag，主要用于无符号运算。

在加法中，如果结果超出了当前寄存器能表示的最大无符号值，就会产生进位，此时 CF = 1。在减法中，如果被减数不够减，需要借位，此时 CF = 1。

; 8 位无符号加法
mov al, 0feh
add al, 2
; 0xfe + 0x02 = 0x100
; al 只能保存低 8 位，结果为 0x00
; 发生进位，CF = 1

再看减法：

mov al, 7fh
sub al, 0ffh
; 0x7f < 0xff
; 无符号视角下发生借位，CF = 1

CF 关注的是无符号数边界，不关心结果在有符号语义下是否合理。判断无符号大小关系时，常见跳转如：

指令 含义 常见判断依据
ja above，大于 CF = 0 且 ZF = 0
jae above or equal，大于等于 CF = 0
jb below，小于 CF = 1
jbe below or equal，小于等于 CF = 1 或 ZF = 1

PF：最低字节奇偶

PF 是 Parity Flag，用于表示运算结果最低字节中 1 的个数是否为偶数。

  • PF = 1：最低字节中 1 的个数为偶数。
  • PF = 0：最低字节中 1 的个数为奇数。
mov eax, 113h
add eax, 1
; eax = 114h
; 低字节为 0x14，也就是 0001 0100
; 其中 1 的个数为 2，是偶数，所以 PF = 1

实际逆向中，PF 不如 ZF、CF、OF 常见。它更多出现在少数校验逻辑、浮点比较相关代码或编译器生成的特定分支里。

AF：低 4 位辅助进位

AF 是 Auxiliary Carry Flag，表示低 4 位向高 4 位是否发生进位或借位。

这个标志位主要服务于早期 BCD 运算。普通逆向分析中遇到频率不高，但理解它有助于完整理解标志寄存器。

mov al, 4eh
add al, 2
; 低 4 位：0xe + 0x2 = 0x10
; 低 4 位向高 4 位进位，所以 AF = 1

可以简单记住：AF 只盯低半字节，也就是最低 4 bit。

ZF：结果是否为零

ZF 是 Zero Flag，是逆向里最常见的标志位之一。

  • 运算结果为 0，ZF = 1。
  • 运算结果不为 0，ZF = 0。
xor eax, eax
; eax = 0
; ZF = 1

mov eax, 2
sub eax, 2
; eax = 0
; ZF = 1

cmp 指令本质上也是减法，只是不保存结果：

cmp eax, 5
je  equal

这段代码可以理解为：

  1. CPU 计算 eax - 5。
  2. 不把结果写回 eax。
  3. 根据计算结果更新标志位。
  4. 如果结果为 0，则 ZF = 1。
  5. je 根据 ZF = 1 跳转到 equal。

常见和 ZF 直接相关的跳转：

指令 含义 判断依据
je / jz 相等 / 为零 ZF = 1
jne / jnz 不相等 / 不为零 ZF = 0

SF：结果符号位

SF 是 Sign Flag，用于表示运算结果最高位是否为 1。

在有符号整数中，最高位通常作为符号位：

  • 最高位为 0：正数或 0。
  • 最高位为 1：负数。
mov al, 7fh
add al, 2
; 0x7f = 0111 1111
; 加 2 后结果为 0x81 = 1000 0001
; 最高位为 1，所以 SF = 1

需要注意，SF = 1 只能说明结果最高位为 1。这通常代表有符号视角下结果为负，但是否发生有符号溢出，还要看 OF。

OF：有符号溢出

OF 是 Overflow Flag，用于判断有符号运算是否超出了当前数据宽度能够表示的范围。

以 8 位有符号数为例，可表示范围是：

-128 ~ 127

如果两个正数相加却得到负数，说明正向溢出；如果两个负数相加却得到正数，说明负向溢出。

mov al, 7fh
add al, 2
; 0x7f 是 127
; 127 + 2 超出 8 位有符号最大值 127
; 结果变成 0x81，从有符号视角看是负数
; OF = 1

再看一个无符号溢出但有符号不溢出的例子：

mov al, 0ffh
add al, 2
; 无符号：255 + 2 超出 8 位范围，CF = 1
; 有符号：-1 + 2 = 1，没有超出有符号范围，OF = 0

这正是 CF 和 OF 最容易混淆的地方：

  • CF 看无符号进位或借位。
  • OF 看有符号结果是否越界。

判断有符号大小关系时，常见跳转会结合 SF 和 OF：

指令 含义 常见判断依据
jg greater，大于 ZF = 0 且 SF = OF
jge greater or equal，大于等于 SF = OF
jl less，小于 SF != OF
jle less or equal，小于等于 ZF = 1 或 SF != OF

DF：字符串操作方向

DF 是 Direction Flag，用于控制字符串操作指令的地址移动方向。

常见字符串指令包括：

  • movs：从源地址复制数据到目标地址。
  • lods：从源地址加载数据到累加器。
  • stos：把累加器中的数据写入目标地址。

DF 的规则：

  • DF = 0：从低地址向高地址处理，ESI 和 EDI 自动递增。
  • DF = 1：从高地址向低地址处理，ESI 和 EDI 自动递减。

设置和清除 DF 的指令：

cld
; Clear Direction Flag，DF = 0

std
; Set Direction Flag，DF = 1

示例：

mov edi, 1000h
mov esi, 2000h
movsd

如果此时 DF = 0，执行 movsd 后，ESI 和 EDI 都会增加 4。如果 DF = 1，执行后它们都会减少 4。

逆向时如何读标志位

看反汇编时，可以按下面的顺序分析：

  1. 找到影响标志位的上一条关键指令，例如 cmp、test、add、sub、xor。
  2. 判断这条指令会影响哪些标志位。
  3. 看后续条件跳转使用的是无符号判断还是有符号判断。
  4. 根据跳转指令反推出源码中的条件语义。

例如：

cmp eax, ebx
ja  loc_greater

ja 是无符号大于，因此这里应按无符号数理解：

if ((unsigned)eax > (unsigned)ebx) {
    goto loc_greater;
}

再看：

cmp eax, ebx
jg  loc_greater

jg 是有符号大于，因此更接近：

if ((int)eax > (int)ebx) {
    goto loc_greater;
}

同样是“大于”，ja 和 jg 的含义并不相同。前者依赖无符号语义，后者依赖有符号语义。这也是分析条件跳转时最容易误判的地方。

解析总结

标志寄存器是汇编条件判断的核心。

  • ZF 判断结果是否为 0。
  • CF 判断无符号进位或借位。
  • SF 观察结果最高位。
  • OF 判断有符号溢出。
  • DF 控制字符串指令的处理方向。

逆向时不要只看跳转指令本身，还要回到前面的 cmp、test、add、sub 等指令，结合标志位变化判断真实逻辑。只要把无符号判断和有符号判断区分清楚，大多数条件跳转都能稳定还原。
