函数调用栈分析(32 位 x86/MSVC)

发表于2026-08-07|更新于2026-08-10|逆向

基础概念

函数调用约定（Calling Convention）是调用方和被调用方之间的一组规则。它规定了函数调用时几个关键问题：

  • 参数按照什么顺序传递
  • 参数通过栈还是寄存器传递
  • 返回值放在哪里
  • 函数调用结束后由谁恢复栈

常见的 32 位调用约定主要有 __cdecl、__stdcall 和 __fastcall。

调用约定 参数传递方向 传输媒介 返回值位置 栈平衡
__cdecl 从右往左 栈 EAX 调用方
__stdcall 从右往左 栈 EAX 被调用方
__fastcall 从右往左 ECX/EDX + 栈 EAX 被调用方

从逆向角度看，调用约定最重要的不是名字，而是它会直接影响反汇编中的参数位置和栈恢复指令。

调用约定

__cdecl

__cdecl 是 C/C++ 中常见的默认调用约定。它的特点是参数从右到左依次压栈，函数返回值通常放在 EAX 中，调用结束后由调用方负责恢复栈。

#include <stdio.h>

int __cdecl fun(int x, int y, int z)
{
    return x + y + z;
}

int main()
{
    fun(1, 2, 3);
    return 0;
}

在反汇编中，调用方通常会先压入参数，然后执行 call，函数返回后再调整 esp。

push 3
push 2
push 1
call fun
add  esp, 0Ch

这里的 add esp, 0Ch 就是调用方清理 3 个参数占用的栈空间。每个参数 4 字节，3 个参数就是 0x0C。

__cdecl 支持可变参数函数，例如 printf。原因也在这里：只有调用方知道自己到底传了多少参数，所以栈必须由调用方清理。

__stdcall

__stdcall 常见于 Windows API。它同样是参数从右到左压栈，返回值放在 EAX 中，但栈由被调用方负责清理。

#include <stdio.h>

int __stdcall fun(int x, int y, int z)
{
    return x + y + z;
}

int main()
{
    fun(1, 2, 3);
    return 0;
}

调用方反汇编通常类似这样：

push 3
push 2
push 1
call fun

函数内部返回时可能出现：

ret 0Ch

ret 0Ch 表示函数返回的同时弹出 12 字节参数空间。也就是说，参数清理工作由被调用函数完成。

逆向 Windows 程序时，如果看到函数结尾是 ret 10h、ret 0Ch 这种形式，通常可以优先考虑它是 __stdcall 一类的调用方式。

__fastcall

__fastcall 的目标是减少压栈开销。它通常会把前两个参数放到寄存器里，例如 ECX 和 EDX，剩余参数再通过栈传递。

#include <stdio.h>

int __fastcall fun(int x, int y, int z)
{
    return x + y + z;
}

int main()
{
    fun(1, 2, 3);
    return 0;
}

典型调用形式可能类似：

push 3
mov  edx, 2
mov  ecx, 1
call fun

这里 x 和 y 通过寄存器传递，z 通过栈传递。分析这种函数时，不要只盯着栈参数，还要注意调用前对 ECX、EDX 的赋值。

函数调用栈细节

函数调用不是单纯跳转到另一个地址执行。一次完整的函数调用通常包含参数传递、保存返回地址、建立栈帧、执行函数体、恢复现场和返回调用方等步骤。

下面用一个简单函数作为例子：

#include <stdio.h>
#include <windows.h>

int fun(int x, int y, int z)
{
    return x + y + z;
}

int main()
{
    fun(1, 2, 3);
    return 0;
}

参数入栈

对于常见的 32 位栈传参，参数一般从右到左压栈。

push 3
push 2
push 1
call fun

压栈完成后，栈顶附近依次保存了参数。因为栈是向低地址增长的，所以最后压入的参数位于更低地址。

保存返回地址

执行 call fun 时，CPU 会自动把下一条指令地址压入栈中，然后跳转到 fun 的入口地址。

这意味着函数内部执行 ret 时，CPU 才知道应该回到哪里继续执行。

可以把 call 粗略理解成两步：

push 返回地址
jmp  fun

建立栈帧

进入函数后，经常能看到经典序言：

push ebp
mov  ebp, esp
sub  esp, 局部变量大小

含义如下：

  • push ebp：保存调用方的栈底
  • mov ebp, esp：建立当前函数的新栈底
  • sub esp, ...：为局部变量申请栈空间

建立栈帧以后，函数内部就可以通过 EBP 稳定访问参数和局部变量。

常见访问方式如下：

[ebp+08h]  ; 第 1 个参数
[ebp+0Ch]  ; 第 2 个参数
[ebp+10h]  ; 第 3 个参数
[ebp-04h]  ; 第 1 个局部变量

为什么第一个参数是 [ebp+08h]？因为：

  • [ebp] 保存的是旧的 EBP
  • [ebp+04h] 保存的是返回地址
  • [ebp+08h] 才是第一个参数

执行函数体

函数体中会读取参数、使用局部变量，并把结果放到返回值寄存器中。对于 32 位整数返回值，通常使用 EAX。

例如：

mov eax, [ebp+08h]
add eax, [ebp+0Ch]
add eax, [ebp+10h]

这段逻辑对应：

return x + y + z;

恢复栈帧并返回

函数结束时，经常能看到：

mov esp, ebp
pop ebp
ret

或者简写成：

leave
ret

其中 leave 等价于：

mov esp, ebp
pop ebp

恢复完成后，ret 会弹出返回地址，并跳回调用方。

如果是 __stdcall，结尾可能是：

ret 0Ch

这表示返回时顺便清理 12 字节参数空间。

调用栈执行流程

一次普通函数调用可以概括为下面 12 个步骤：

步骤 描述
1 调用方按照调用约定传递参数
2 call 指令保存返回地址
3 被调用方保存调用方栈底
4 被调用方建立新的栈帧
5 为局部变量申请栈空间
6 必要时保存寄存器环境
7 Debug 编译下局部变量可能初始化为 0xCCCCCCCC
8 执行函数体逻辑
9 恢复寄存器环境
10 释放局部变量空间
11 恢复调用方栈底
12 返回调用方，并按调用约定清理参数空间

理解这套流程后，在调试器里观察 ESP、EBP、EAX 的变化，会比单纯看源码更直观。

逆向分析中的判断方法

看参数位置

如果函数内部大量访问 [ebp+08h]、[ebp+0Ch]，说明参数来自栈。

如果调用前对 ECX、EDX 赋值明显，再进入函数使用这两个寄存器，可能是 __fastcall 或成员函数调用。

看返回指令

ret 和 ret n 是判断调用约定的重要线索。

ret       ; 通常由调用方清理栈
ret 0Ch   ; 被调用方返回时清理参数

但这不是绝对规则，实际分析时还需要结合调用点一起判断。

看调用点是否调整 ESP

如果调用后出现：

add esp, 0Ch

说明调用方清理了参数空间，常见于 __cdecl。

如果调用后没有调整 ESP，而函数结尾是 ret 0Ch，通常是 __stdcall。

看返回值使用方式

调用结束后，如果马上使用 EAX，通常说明函数返回值保存在 EAX 中。

call fun
test eax, eax
jz   short loc_fail

这类模式在判断函数返回状态时非常常见。

分析总结

函数调用栈的核心不是死记调用约定，而是理解调用方和被调用方之间如何协作。

分析重点 需要关注的内容 常见线索 逆向意义
参数来源 参数通过栈还是寄存器传递 [ebp+08h]、[ebp+0Ch]、ECX、EDX 判断函数参数数量、顺序和传参方式
返回值位置 返回值通常由哪个寄存器保存 EAX、test eax, eax、cmp eax, ... 判断函数返回状态、错误码或计算结果
栈恢复方式 调用方还是被调用方负责清理参数 add esp, xx、ret xx 辅助判断 __cdecl、__stdcall 等调用约定
栈帧结构 当前函数如何建立和恢复栈帧 push ebp、mov ebp, esp、leave 区分参数、局部变量和返回地址
调用关系 调用方和被调用方如何协作 push、call、ret 还原函数边界、调用链和数据流向

函数调用栈分析的关键，是把 push、call、ret、leave、add esp、[ebp+xx] 这些指令放到完整调用流程里理解。只要能判断参数、返回值、栈平衡和栈帧变化，反汇编里的函数调用关系就会清晰很多。
